  Supports the exact 8-parameter overload:
  void record(Integer actorUserId, String actorRole, String action,
              String targetDataType, String targetRefId, String accessStatus,
              String oldValue, String newValue)

Field Mapping & Conventions Used:
- actorUserId: Authenticated user ID (from parameter or `CurrentActor.current()`).
- actorRole: Resolved role via `resolveActorRole(isStaff)` ("FNB_STAFF" or "CUSTOMER").
- action: "CANCEL_MEAL_ORDER" (consistent with HSWRMS audit action verbs).
- targetDataType: "MealOrder" (identifies the affected entity type).
- targetRefId: String.valueOf(order.getMealOrderId()) (identifies specific order).
- accessStatus: AuditLogService.SUCCESS ("SUCCESS").
- oldValue: currentStatus ("PENDING", "PREPARING", or "READY").
- newValue: "CANCELLED; Reason: " + trimmedReason (captures transition & reason).

Defensive Truncation & Data Minimization:
- `AuditLogService` automatically truncates `action` to 150 chars, `targetDataType` 
  to 100 chars, `targetRefId` to 100 chars, and `oldValue`/`newValue` to 500 chars.
- Data Minimization: The audit trail captures only the operational meal cancellation 
  reason (e.g., "Out of fresh lettuce"). Medical, clinical, allergy, or financial 
  data is strictly excluded from `AuditLog`.
- Access Control: `dbo.AuditLog` is queryable exclusively by authorized M6 Admin 
  users via `AdminDashboardController` / `AuditLogRepository`, and is never exposed 
  in customer-facing `MealOrderDto`.

5. TRANSACTION AND FAILURE BEHAVIOR
================================================================================
Transaction Semantics:
- `MealOrderServiceImpl` is annotated with `@Transactional` (Spring `PROPAGATION_REQUIRED`).
- `AuditLogService.record` is annotated with `@Transactional` (Spring `PROPAGATION_REQUIRED`).
- They execute inside the identical database transaction boundary.

Failure Handling:
- Execution order in `cancelOrderInternal`:
    1. Validation of status and reason.
    2. Invocation of `auditLogService.record(...)`.
    3. Mutation `order.setOrderStatus("CANCELLED")` and `mealOrderRepository.save(order)`.
- If `auditLogService.record(...)` fails (e.g., storage error, disk full, DB timeout):
    * The exception is NOT caught or swallowed.
    * It propagates out to the caller.
    * Spring marks the active transaction for immediate rollback.
    * The order status in the database and entity state remain unchanged (not CANCELLED).
    * No false or partial cancellation is reported to the client.
