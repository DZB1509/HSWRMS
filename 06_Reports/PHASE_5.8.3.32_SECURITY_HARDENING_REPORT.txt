   that halts compilation/execution (SET NOEXEC ON) if a placeholder is detected.

   SqlServerTestConfigValidator.

6. SECURITY ISSUES FOUND & RESOLUTION
--------------------------------------------------------------------------------
Issue 1: Overprivileged Smoke Test Role (db_datareader)
- Finding: Previous drafts granted db_datareader. The smoke test queries only
  scalar system functions @@VERSION and DB_NAME(), which require no table access.
- Resolution: Removed db_datareader grant. Granted ONLY database CONNECT on
  [HSWRMS_TEST]. System functions are callable via the 'public' role.

Issue 2: Executable Default Password Placeholder
- Finding: Draft script contained WITH PASSWORD = N'CHANGE_ME_STRONG_PASSWORD!'.
  A developer executing without careful review could provision a known password.
- Resolution: Replaced with SQLCMD variable $(TEST_PASSWORD). Added a pre-execution
  guard that evaluates the variable; if empty or matching placeholder, it raises
  an error and activates SET NOEXEC ON to halt all further execution.

Issue 3: Unsafe Object Re-use (Lack of Fail-Closed Checks)
- Finding: IF NOT EXISTS skipped creation without verifying health or security
  of existing objects. If HSWRMS_TEST existed in OFFLINE/SUSPECT state, or if
  hswrms_test_user existed with sysadmin privileges, the script would silently proceed.
- Resolution: Added explicit checks in draft script and Java validator:
  * Database state must be ONLINE.
  * Login must not be disabled.
  * Login must not have sysadmin role.
  * Default database must be HSWRMS_TEST.
  * Login must not be mapped in primary database HSWRMS.

Issue 4: 'sa' Account Test Usage Risk
- Finding: If a developer attempted to use 'sa' via environment variables,
  the validator did not explicitly block it.
- Resolution: Added an explicit check in SqlServerTestConfigValidator.validate(...)
  that throws an immediate SAFETY VIOLATION IllegalStateException if 'sa' is used.
