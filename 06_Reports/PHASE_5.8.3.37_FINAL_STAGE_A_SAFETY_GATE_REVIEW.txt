5. TASK 3: SQLCMD MODE VERIFICATION AUDIT
================================================================================
A. Technical Mechanism Analysis:
  1. The SQL Server database engine has NO native session property, system function,
     or DMV that reports "SQLCMD mode is enabled". SQLCMD is strictly a client-side
     preprocessor protocol (implemented in 'sqlcmd.exe' and SSMS editor).
  2. In 'draft_provision_hswrms_test.sql', the verification pattern is:
     Line 44: ':setvar SQLCMD_MODE_CHECK "SQLCMD_ACTIVE"'
     Line 47: 'IF ''$(SQLCMD_MODE_CHECK)'' <> ''SQLCMD_ACTIVE'''
  3. Does it merely check a caller-controlled variable?
     - Yes, in the sense that ':setvar' assigns a preprocessor macro.
     - However, it critically verifies that CLIENT-SIDE MACRO EXPANSION is active.
     - If the client preprocessor is NOT running, '$(SQLCMD_MODE_CHECK)' is NOT replaced.

B. Safe Empirical Testing Across Execution Clients:
  1. CLI Execution (sqlcmd.exe):
     - Line 44 ':setvar' is intercepted by the preprocessor and stripped.
     - In Batch 3, '$(SQLCMD_MODE_CHECK)' is expanded to 'SQLCMD_ACTIVE'.
     - The engine evaluates 'IF ''SQLCMD_ACTIVE'' <> ''SQLCMD_ACTIVE''' (FALSE).
     - Execution proceeds.
  2. SSMS with SQLCMD Mode ENABLED:
     - SSMS SQLCMD parser intercepts ':setvar' and expands '$(SQLCMD_MODE_CHECK)'.
     - Evaluation matches CLI behavior; pre-check passes.
  3. Client with SQLCMD Mode DISABLED (Standard T-SQL Client / SSMS without SQLCMD):
     - Tested safely via ADO.NET submitting identical batch sequences:
       * Batch 1 (':on error exit'): Engine raises "Msg 102, Incorrect syntax near ':'".
       * Batch 2 (':setvar ...'): Engine raises "Msg 102, Incorrect syntax near ':'".
       * Batch 3 ('IF ''$(SQLCMD_MODE_CHECK)'' <> ''SQLCMD_ACTIVE'''):
         Because macro substitution never occurred, the engine evaluates literal
         varchar comparison: ''$(SQLCMD_MODE_CHECK)'' <> ''SQLCMD_ACTIVE''.
         This evaluates to TRUE!
       * The engine executes the IF body: raises FAIL CLOSED error and runs SET NOEXEC ON.
       * Subsequent batches submitted on the connection are parsed only; 0 statements execute.
  4. Precise Audit Conclusion:
     The SQLCMD_MODE_CHECK mechanism reliably detects whether the client preprocessor
     is active via round-trip macro substitution. In non-SQLCMD clients, colon syntax
     errors occur and unexpanded macro tokens trigger immediate fail-closed shutdown.
