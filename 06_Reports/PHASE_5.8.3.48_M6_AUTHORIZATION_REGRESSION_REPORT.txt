3. AUTHORIZATION BEHAVIOR OF EACH RELEVANT BRANCH
--------------------------------------------------------------------------------
Branch Analysis for `AdminDashboardController.getSystemOverview()`:

  [Branch 1: Administrator User]
    - Evaluation: `actor.admin() == true`.
    - Short-circuit: The expression evaluates to `true` immediately without evaluating
      the second operand.
    - Behavior: Admin receives all 3 widgets (`auditActivity`, `businessParameters`,
      `managerDelegations`) with `available = true`, active counts, and metadata.
    - Status: PASS (Verified by `AdminControllersSecurityTest.adminCanAccessAllAdminEndpoints`
      and `SECURITY-14`).

  [Branch 2: Non-Administrator with Delegated S55_ADMIN_WIDGETS:V]
    - Evaluation: `actor.admin() == false`, `permissionService != null`, and
      `permissionService.userHas(actor.userId(), "S55_ADMIN_WIDGETS", "V") == true`.
    - Behavior: Manager caller who holds an ACTIVE time-bound delegation receives
      all 3 widgets with `available = true` and operational count data.
    - Status: PASS (Verified by `AdminControllersSecurityTest.SECURITY-13`).

  [Branch 3: Non-Administrator without S55_ADMIN_WIDGETS:V]
    - Evaluation: `actor.admin() == false`, `permissionService != null`, and
      `permissionService.userHas(actor.userId(), "S55_ADMIN_WIDGETS", "V") == false`.
    - Behavior: Manager caller receives `auditActivity` with `available = true`, but
      both `businessParameters` and `managerDelegations` return `available = false`,
      `value = null`, and `note = "Requires administrative widgets permission"`.
      No sensitive administrative metrics are leaked.
    - Status: PASS (Verified by `AdminControllersSecurityTest.SECURITY-10`).

  [Branch 4: Missing / Null PermissionService (Fail-Closed Execution)]
    - Evaluation:
      * For Non-Admin: `permissionService == null` -> `(null != null && ...)` evaluates
        to `false`. `canViewAdminWidgets` becomes `false`. Non-admin caller receives
        masked widgets (`available = false`, `value = null`). Zero NullPointerException.
      * For Admin: `actor.admin() == true` -> Admin maintains root access regardless
        of PermissionService availability (`available = true`). Zero NullPointerException.
    - Status: PASS (Verified by `AdminControllersSecurityTest.SECURITY-14`).

  [Branch 5: Unauthenticated or Unauthorized Screen Entry]
    - Evaluation: Unauthenticated caller or role without S55:V permission (e.g., CUSTOMER).
    - Behavior: Denied at entry by Spring Security `@PreAuthorize("@perm.has('S55','V')")`
      with HTTP 401 Unauthorized or HTTP 403 Forbidden.
      Emits audit log entry `Access Denied` (target: Screen:S55, status: DENIED).
    - Status: PASS (Verified by `AdminControllersSecurityTest.SECURITY-01`, `SECURITY-02`).

5. CONFIRMED DEFECTS & MINIMAL CORRECTIONS
--------------------------------------------------------------------------------
Defect 1 (Fixed in Phase 5.8.3.47):
  - Location: `AdminDashboardController.java:111`
  - Issue: Direct call `permissionService.userHas(...)` risked NullPointerException
    if `PermissionService` was not injected or unavailable during controller execution.
  - Minimal Correction: Guarded with null check:
    `(permissionService != null && permissionService.userHas(actor.userId(), "S55_ADMIN_WIDGETS", "V"))`.
  - Impact: Non-admin fails closed to `canViewAdminWidgets = false`, avoiding 500 error
    while preventing unauthorized metric disclosure. Admin access preserved.

Defect 2 (Identified and Resolved in Phase 5.8.3.48):
  - Location: `AdminControllersSecurityTest.java` (Test Assertion Gap)
  - Issue: `SECURITY-10` only asserted HTTP 200 and `title = "System Operational Overview"`,
    failing to verify that the widgets `businessParameters` and `managerDelegations`
    were actually masked (`available = false`). Furthermore, no tests asserted behavior
    when manager holds active delegation for `S55_ADMIN_WIDGETS` or when `PermissionService`
    is null.
  - Minimal Correction:
    1. Added JSON path assertions to `SECURITY-08` verifying admin sees all widgets with
       `available = true`.
    2. Added JSON path assertions to `SECURITY-10` verifying non-delegated manager sees
       widgets with `available = false` and explanatory note.
    3. Added test `SECURITY-13` verifying manager with active `S55_ADMIN_WIDGETS` delegation
       receives widgets with `available = true`.
    4. Added test `SECURITY-14` verifying controller fails closed without NullPointerException
       when instantiated with null `PermissionService`.
  - Verification: All 14 tests in `AdminControllersSecurityTest` compile and pass cleanly.

7. UNRESOLVED POLICY AMBIGUITIES & VERIFICATION GAPS
--------------------------------------------------------------------------------
A. Architectural Consistency Gap in `PermissionEvaluator.java`:
   - Observation: In `AdminDashboardController.java` and `BusinessParameterService.java`,
     null checks are explicitly performed on `PermissionService` to fail closed for
     non-administrators while allowing administrators root bypass.
   - Potential Inconsistency: In `PermissionEvaluator.java:39`:
     `boolean allowed = active && ((actor.admin() && !isSensitiveData) || permissionService.userHas(actor.userId(), screen, action));`
     If `PermissionEvaluator` were ever invoked with a null `permissionService` for a
     non-admin actor, line 39 would throw NullPointerException instead of failing closed.
   - Note: In Spring container deployment, `PermissionService` is a singleton `@Service`
     bean and is never null under normal DI. However, for defensive uniformity across
     all M6 components, a future refactoring could add `permissionService != null && ...`
     to `PermissionEvaluator.java`.
   - Classification: REQUIRES DESIGN DECISION (Minor hardening recommendation).
