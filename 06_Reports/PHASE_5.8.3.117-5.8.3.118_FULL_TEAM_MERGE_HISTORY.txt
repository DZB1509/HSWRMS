11.2 REMAINING RISKS AND LIMITATIONS
1. Live SQL Server Dialect & Concurrency Behavior:
   All automated tests executed against in-memory H2 (`MODE=MSSQLServer`). Live 
   Microsoft SQL Server 2022 exhibits dialect differences including table lock 
   hints (`WITH (UPDLOCK, HOLDLOCK)`), transaction isolation levels (`READ COMMITTED 
   SNAPSHOT`), sequence caching, and datetime precision (`DATETIME2` vs `TIMESTAMP`). 
   These behaviors cannot be verified without executing against live `HSWRMS_TEST`.
2. Third-Party Gateway Runtime Integration:
   VNPay IPN callback validation and Google/Facebook SSO redirects have been verified 
   only through mocked unit tests. End-to-end integration requires live outbound 
   network access, valid client secrets, and external redirect URI reachability.
3. Multi-Module Lifecycle Traversal:
   While each module's unit and slice tests pass independently, a complete end-to-end 
   user journey (Guest books retreat -> Receptionist checks in guest -> Guest orders 
   dinner in KDS -> Guest attends spa session -> Cashier generates single folio and 
   prints VAT invoice) has not been verified in a running deployment.
4. Concurrent Inventory & Booking Contention:
   High-concurrency room booking and ingredient deduction under active connection 
   pooling require dedicated load/stress testing to confirm lock acquisition timing 
   and deadlock avoidance.
