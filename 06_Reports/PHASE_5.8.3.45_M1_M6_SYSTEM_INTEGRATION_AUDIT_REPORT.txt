2. CROSS-MODULE FLOW AUDIT & END-TO-END VALIDATION MATRIX
--------------------------------------------------------------------------------
Flow 1: Booking -> Check-In -> Folio Initialization
- Description: Customer booking verified -> Mandatory residence record collected ->
  Physical villa assigned -> Booking status becomes CHECKED_IN -> Default Folio initialized.
- Audit Findings:
  * ReceptionistOperationService.assignVillaAndCheckIn enforces residence record check
    before physical villa assignment.
  * FolioBillingService.getFolioByBookingId / postFolioCharge lazily initializes default
    FolioEntity on first access, binding it seamlessly to RetreatBooking.
- Status: VERIFIED END-TO-END (Green)

Flow 2: Booking -> Spa / F&B Orders -> Charge Posting -> Consolidated Invoice
- Description: Extra spa sessions or a-la-carte meal orders post charges to guest folio;
  consolidated invoice aggregates room package balance + extras + VAT.
- Audit Findings:
  * Previous OI-01 gap resolved: DefaultBillingAdapter now delegates extra spa session
    charges directly to FolioBillingService.postFolioCharge.
  * Daily meal orders (DAILY_MEAL) correctly rejected by CANNOT_CHARGE_INCLUDED_SERVICE.
  * Duplicate postings prevented via existsBySourceSpaSessionId / existsBySourceMealOrderId
    and pessimistic write locks.
- Status: VERIFIED END-TO-END (Green - Tested via m3BillingAdapterPostsExtraSpaChargeDirectlyToFolio)

Flow 3: In-Flight Orders -> Billing Guard -> Checkout Halt
- Description: Active spa sessions (SCHEDULED/RESCHEDULING) or dining orders
  (PENDING/PREPARING/READY) trigger billing guard, preventing invoice generation or checkout.
- Audit Findings:
  * validateBillingGuard enforces strict terminal status requirements before invoice/checkout.
  * Throws UNSETTLED_SERVICE_ORDERS with exact count of pending sessions/orders.
- Status: VERIFIED END-TO-END (Green - Tested via billingGuardBlocksWhenScheduledSpaSessionExists)

Flow 4: Payment -> Balance Validation -> Checkout Finalization -> Villa State Update
- Description: Payment settles remaining balance -> finalizeCheckout verifies zero unpaid
  obligations -> atomically closes Folio, completes Booking, and marks Villa as NEEDS_CLEANING.
- Audit Findings:
  * Fully idempotent: duplicate checkout calls for already COMPLETED stay return clean
    idempotent response without altering database records.
  * Detects and rejects contradictory states (e.g. folio closed but booking checked in).
  * Automatically transitions PhysicalVilla to NEEDS_CLEANING for housekeeping dispatch.
- Status: VERIFIED END-TO-END (Green - Tested via finalizeCheckoutSuccessPath)

Flow 5: Right Delegation -> Dynamic Permission Evaluation -> Administrative Access
- Description: Admin delegates administrative screens (e.g. S50 Parameters) to active Manager ->
  PermissionService evaluates effective rights -> Manager accesses authorized endpoints.
- Audit Findings:
  * Self-delegation blocked at both Service and Controller levels.
  * Expired or revoked delegations immediately cease to grant access.
  * Manager without active delegation attempting to edit business parameters is rejected (403).
- Status: VERIFIED END-TO-END (Green - Tested via managerWithDelegationCanUpdateParameters)

Flow 6: System Configuration Changes -> Validation -> Audit Log Trail
- Description: Configuration parameters validated against data types and min/max bounds;
  all modifications and validation rejections logged to AuditLog.
- Audit Findings:
  * Out-of-bounds updates throw BusinessRuleException("M6-MSG-04") and log FAILED audit record.
  * Non-editable parameters protected against non-admin edits.
- Status: VERIFIED END-TO-END (Green - Tested via updateOutOfRangeParameter)
