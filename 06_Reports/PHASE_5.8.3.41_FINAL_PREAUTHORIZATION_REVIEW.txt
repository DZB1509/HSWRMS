8. TECHNICAL REVIEW OF PASSWORD HANDLING & MANAGED CLR LIMITATIONS
================================================================================
Password Lifecycle Trace in provision_hswrms_test.ps1:
  1. Capture: User input is captured via Read-Host -AsSecureString into an encrypted
     System.Security.SecureString object in unmanaged DPAPI memory.
  2. Unmanaged Conversion: Marshal::SecureStringToBSTR allocates a raw COM BSTR in
     unmanaged memory holding decrypted characters.
  3. Managed String Allocation: Marshal::PtrToStringBSTR copies the unmanaged BSTR
     characters into an immutable managed System.String instance ($plainPass) on the
     CLR garbage-collected (GC) heap.
  4. TDS Transmission: System.Data.SqlClient reads $plainPass and serializes characters
     into TDS RPC network buffers sent over TCP to SQL Server.
  5. Cleanup in finally block:
     [Marshal]::ZeroFreeBSTR($bstr)
     $plainPass = $null
     [System.GC]::Collect()

Critical Security Assessment Regarding Managed Memory:
  - While ZeroFreeBSTR guarantees that the unmanaged BSTR memory block is overwritten
    with zeroes and freed back to the OS memory pool, it does NOT zero the immutable
    managed System.String object on the CLR heap.
  - In .NET, System.String objects are immutable and allocated on the managed heap.
    Setting $plainPass = $null merely clears the reference pointer on the evaluation stack;
    the string characters remain on the GC heap until the garbage collector compacts
    or sweeps the memory page, and even then the underlying bytes may persist until
    re-allocated and overwritten.
  - Furthermore, TDS serialization buffers created by the ADO.NET driver during
    packetization also reside in process memory until collected.
  - Process memory may also be paged out to disk by Windows (pagefile.sys or hiberfil.sys)
    under memory pressure or system sleep.
  - Honest Conclusion: No local script in .NET can provide an absolute guarantee of
    zeroing managed string memory without unsafe pointer pinning. The true security
    objective is pragmatic risk elimination:
      * Prevent command-line argument inspection via Get-Process, Task Manager, Event 4688.
      * Prevent recording in PowerShell PSReadLine ConsoleHost_history.txt.
      * Prevent persisting credentials into git-tracked .sql files or commit diffs.
      * Zero the unmanaged memory buffers immediately upon completion.
    The implemented script satisfies all of these objectives completely.
