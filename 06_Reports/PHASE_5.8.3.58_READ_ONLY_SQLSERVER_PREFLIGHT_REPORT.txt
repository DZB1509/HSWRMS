--------------------------------------------------------------------------------

(Inspected statically without execution).

A. The Beginning of `schema.sql` (Lines 18-28):
   ```sql
   18: USE [master];
   19: GO
   20: 
   21: IF DB_ID(N'HSWRMS') IS NULL
   22: BEGIN
   23:     CREATE DATABASE [HSWRMS];
   24: END
   25: GO
   26: 
   27: USE [HSWRMS];
   28: GO
   ```

B. Execution Context Hazard Analysis:
   - If an administrator or script invokes:
     `sqlcmd -S localhost -d HSWRMS_TEST -i 05_Development/database/schema.sql`
   - The CLI parameter `-d HSWRMS_TEST` sets the initial database context.
   - However, SQLCMD parses and executes batch-by-batch:
     1. Batch 1 (lines 18-19): Switches context to `master`.
     2. Batch 2 (lines 21-25): Asserts `HSWRMS` database existence.
     3. Batch 3 (lines 27-28): Explicitly executes `USE [HSWRMS]; GO`.
   - Result: All subsequent 1,193 lines of DDL (creating tables, constraints, indexes,
     and triggers) are executed against the primary database `HSWRMS`, NOT `HSWRMS_TEST`!
   - This overrides command-line `-d HSWRMS_TEST` completely.

C. Mandatory Mitigation Requirement:
   - The original `schema.sql` MUST NOT be passed directly to SQLCMD for test provisioning.
   - A sanitized payload must be prepared prior to Stage 4 execution:
     Lines 18-28 must be stripped, or line 27 replaced with `USE [HSWRMS_TEST]; GO`.
