4. INTENTIONAL TRANSFORMATIONS FROM ORIGINAL SCHEMA

Only three intentional, safe transformations were performed:

A. Removal of Destructive & Context-Switching Statements:
   - Source Lines 18-28 Removed:
     ```sql
     USE [master];
     GO
     IF DB_ID(N'HSWRMS') IS NULL
     BEGIN
         CREATE DATABASE [HSWRMS];
     END
     GO
     USE [HSWRMS];
     GO
     ```
   - Rationale: Eliminates the fatal hazard where executing the script via SQLCMD
     switches the session context to master and then to primary database HSWRMS.

B. Insertion of Explicit Test Target Context and Fail-Closed Guard:
   - Target Lines 19-29 Inserted:
     ```sql
     USE [HSWRMS_TEST];
     GO

     -- Target Verification Guard: Fail-closed assertion ensuring execution cannot proceed outside HSWRMS_TEST
     IF DB_NAME() <> N'HSWRMS_TEST'
     BEGIN
         PRINT 'CRITICAL TARGET CONTEXT FAILURE: Active database is [' + DB_NAME() + ']; expected [HSWRMS_TEST]. Aborting immediately.';
         SET NOEXEC ON;
         THROW 51000, N'CRITICAL TARGET CONTEXT FAILURE: Execution halted because current database is not HSWRMS_TEST.', 1;
     END
     GO
     ```
   - Rationale:
     1. `USE [HSWRMS_TEST]; GO` switches the active session directly into the dedicated test database.
     2. The Target Verification Guard inspects `DB_NAME()`. If for any reason the context is NOT
        `HSWRMS_TEST`, it executes `SET NOEXEC ON;` followed by `THROW 51000`.
     3. In Microsoft SQL Server, `SET NOEXEC ON` forces the engine to compile but REFUSE TO EXECUTE
        any subsequent statements in the session. This guarantees fail-closed behavior across all batches.

C. Updated Verification Confirmation Message:
   - Source Line 1220:
