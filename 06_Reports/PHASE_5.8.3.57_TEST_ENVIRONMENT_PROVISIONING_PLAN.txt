3. PROVISIONING SCRIPT SAFETY & RISK ASSESSMENT
--------------------------------------------------------------------------------
Inspected File: `05_Development/database/scripts/provision_hswrms_test.ps1` (440 lines).

A. Parameter Validation & Boundary Safety:
   - Compile-Time Constraints:
     * `$DatabaseName`: `[ValidateSet("HSWRMS_TEST")]` (Line 61).
     * `$LoginName`: `[ValidateSet("hswrms_test_user")]` (Line 65).
     * `$ServerInstance`: `[ValidateNotNullOrEmpty()]` (Line 57).
   - Runtime Assertions (`Test-HswrmsProvisioningInput`, lines 99-147):
     * Server: regex check `^[A-Za-z0-9_\-\.\\]+$` prevents injection in connection string.
     * Database: strictly `$Db -eq 'HSWRMS_TEST'`.
     * Login: strictly `$Login -eq 'hswrms_test_user'`.
     * Password: length 12..128 chars, whitespace-only rejected, prohibited placeholders
       (`REPLACE_WITH_STRONG_PASSWORD_BEFORE_EXECUTION`, `CHANGE_ME_STRONG_PASSWORD!`) rejected,
       unresolved macro prefixes (`$(`) rejected.

B. Injection Resistance & Credential Transport:
   - Transmits password as typed RPC parameter `System.Data.SqlDbType.NVarChar(128)` via
     the Tabular Data Stream (TDS) protocol (Line 333).
   - Uses server-side `QUOTENAME(@password, '''')` in dynamic SQL executed via
     `sys.sp_executesql` (Line 329). Single quotes within the password are automatically
     escaped by the database engine.
   - Eliminates SQLCMD text macro substitution collision risks entirely.

C. Safeguards Protecting Primary Database `HSWRMS`:
   - Stage 1.4 (Lines 291-304): Queries `sys.databases WHERE name = 'HSWRMS'`. If present,
     connects to `HSWRMS` and asserts that `hswrms_test_user` has 0 mappings in
     `sys.database_principals`. Fails closed if mapped.

D. Fail-Closed Idempotency & Object Lifecycle:
   - By default, `-AllowExistingDb` and `-AllowExistingLogin` are `$false`.
   - If `HSWRMS_TEST` or `hswrms_test_user` exists, script throws `FAIL CLOSED` immediately.
   - If `-AllowExistingDb` is authorized: verifies database is `ONLINE`.
   - If `-AllowExistingLogin` is authorized: verifies login is enabled, has default DB
     in `('HSWRMS_TEST', 'master')`, has ZERO server roles (`sysadmin`, etc.), and has
     ZERO server permissions other than `CONNECT SQL`.

E. Partial Failure Risk & Recovery Analysis:
   - The script creates objects sequentially:
     Stage 2: `CREATE DATABASE [HSWRMS_TEST]`
     Stage 3: `CREATE LOGIN [hswrms_test_user]`
     Stage 4: `CREATE USER [hswrms_test_user] ... GRANT CONNECT`
   - If Stage 2 succeeds but Stage 3 fails (e.g., password complexity failure on OS):
     `HSWRMS_TEST` exists without login.
   - Recovery Behavior: The script does NOT drop `HSWRMS_TEST`. Rerunning with corrected
     password and `-AllowExistingDb` resumes cleanly without data loss.

F. DryRun & WhatIf Verification:
   - Lines 180-196 implement complete safe dry-run mode via `-DryRun` and `-WhatIf`.
   - Validates all client-side inputs, parameter bounds, and quoting formulas with
     ZERO database connections opened and ZERO mutations performed.

8. ROLLBACK & RECOVERY CONSIDERATIONS
--------------------------------------------------------------------------------
1. Failure in Stage 3 (Database / Login creation):
   - Database created, login failed: Rerun `provision_hswrms_test.ps1` with `-AllowExistingDb`
     after correcting password complexity.
   - Login created, database failed: Rerun with `-AllowExistingLogin`.
   - Neither situation requires dropping or modifying `HSWRMS`.
2. Failure in Stage 4, 5, or 6 (DDL / Seeding failure):
   - Because `HSWRMS_TEST` is completely isolated, a clean recovery is performed by dropping
     only `HSWRMS_TEST` (`DROP DATABASE [HSWRMS_TEST];`) and repeating from Stage 3.
   - Primary database `HSWRMS` remains completely untouched.
3. Test Credential Desynchronization:
   - If password mismatch occurs (Error 18456), synchronize password using:
     `ALTER LOGIN [hswrms_test_user] WITH PASSWORD = N'...'`.
